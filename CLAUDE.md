## Project Context

**Stack:** TypeScript library (zero dependencies), Aho-Corasick based profanity checker
**Package manager:** pnpm
**Primary language:** TypeScript

## Project Structure

pnpm workspace — packages live under `packages/*`.

```
packages/bleepit/          ← The checker (published as `bleepit`)
  src/
    index.ts       ← Public API entry point
    checker.ts     ← ProfanityChecker class (find/censor/isProfane, addWords/removeWords)
    automaton.ts   ← Aho-Corasick automaton (O(n) scanning core)
    normalizer.ts  ← Text normalization (leet-speak, separators, diacritics)
    types.ts       ← Shared types
    lists/         ← Per-language wordlists (en, es, fr, de) + index
  test/
    checker.test.ts ← Unit tests (vitest)
    bench.test.ts   ← Benchmark tests
  site/
    index.html     ← Live demo page
    main.ts        ← Demo logic (source of truth — edit this, not the bundle)
    bleepit.bundle.js ← Built output; regenerate with `pnpm site:build`, don't hand-edit

packages/ocr/             ← Image support (published as `@bleepit/ocr`)
  src/
    index.ts       ← Public API entry point
    checker.ts     ← ImageProfanityChecker (isProfane/find/redact/findInWords)
    spans.ts       ← OCR-word ↔ text-offset mapping
    types.ts       ← OcrEngine contract + shared types
  test/            ← Unit tests (vitest)
```

## Component & Code Reuse

- Check `packages/bleepit/src/lists/` before adding new profanity entries — extend the relevant language file
- Extend `ProfanityChecker` (`packages/bleepit/src/checker.ts`) rather than adding parallel detection logic
- Extract logic used in 2+ places into a shared helper in `normalizer.ts` or `automaton.ts`
- Inline logic stays inline until it recurs

---

## Stack Conventions

- No runtime dependencies — keep it that way (this is a core selling point: "zero dependencies, isomorphic"). Companion packages take `bleepit` as a peer dependency, never a bundled one
- Each package exports its public API from its own `src/index.ts`; keep internals (automaton, normalizer, spans) unexported unless needed
- `dist/` is generated per package via `tsup` (`pnpm build`) — never hand-edit or commit ad hoc changes there
- `packages/bleepit/site/bleepit.bundle.js` is generated via `esbuild` (`pnpm site:build`) — edit `site/main.ts`, then rebuild

## Git Scopes

Use these scopes in commit messages:

- `(checker)` — ProfanityChecker core logic (find/censor/isProfane)
- `(automaton)` — Aho-Corasick automaton
- `(normalizer)` — Text normalization (leet, separators, diacritics)
- `(lists)` — Wordlist additions/changes per language
- `(ocr)` — The `@bleepit/ocr` image package
- `(site)` — Live demo page
- `(config)` — Build/config/tooling

---

## Off Limits

- Don't hand-edit any `dist/` — they're generated by `pnpm build`
- Don't hand-edit `packages/bleepit/site/bleepit.bundle.js` — it's generated by `pnpm site:build` from `site/main.ts`

## Commands to Know

Run from the repo root; these fan out across every package:

```bash
pnpm build        ← Build all packages (tsup)
pnpm test         ← Run all tests before committing (vitest)
pnpm lint         ← Type-check all packages (tsc --noEmit)
pnpm bench        ← Run benchmark suite
pnpm site:build   ← Rebuild the live demo bundle after editing site/main.ts
pnpm size         ← Build and report gzip size of bleepit's dist/index.js
pnpm changeset    ← Record a user-visible change for the changelog
```

Single-package work uses a filter:

```bash
pnpm --filter bleepit test:watch
pnpm --filter @bleepit/ocr test
```

## Notes

- Wordlists (`packages/bleepit/src/lists/*.ts`) contain profane language by necessity — this is expected content for this library, not a violation of the "no profanity in repo" norm.
- The live demo (`packages/bleepit/site/`) is public-facing; prefer milder example text in presets over the most severe wordlist entries.
- Mild words (`damn`, `crap`, `hell`) are deliberately absent from the English list — don't add them to make a test pass; fix the test's fixture instead.
- `CONTRIBUTING.md` is the public contract for the same conventions this file covers. Change both together or they drift.
- `main` exists on `origin`; branch from it and open PRs against it.
